## 四、接手时的问题与处置结果

```text
┌────┬──────────────────────────────────┬────────────────────┐
│ 序 │ 问题                             │ 处置               │
├────┼──────────────────────────────────┼────────────────────┤
│ 1  │ 离线检测与蜂鸣器告警恒不生效     │ 已删除死链         │
│ 2  │ OLED 电量恒显 0                  │ 已删除显示与采样   │
│ 3  │ 遥控器运行时校准不可用           │ 用户决定搁置       │
│ 4  │ Infantry_robot 等宏未提交        │ 已提交             │
└────┴──────────────────────────────────┴────────────────────┘
```

第 1 项的执行有一个必须记录的判断：`toe_is_error(DBUS_TOE)` 同时承担两件事，既驱动蜂鸣器，也决定遥控器数据非法时是否给底盘发零电流。该判断常假意味着这个保护一直没生效。按用户确认，删除告警链但保留保护，改用 `remote_control.c` 里现成的 `RC_data_is_error()`。

区别在副作用：`toe_is_error` 只读状态，`RC_data_is_error()` 会顺带把 `rc_ctrl` 归零并强制两个开关回下档。因此现在遥控器数据非法时，底盘收到零电流且遥控数据被清空，是保护真正生效的状态，不是行为倒退。

第 3 项搁置不影响开机校准：`main()` 的 `cali_param_init()` 仍会从 Flash 读取已校准参数并回灌。
