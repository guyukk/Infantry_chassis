# 6020 独立台架测试

本测试固件只使用底盘板、DBUS 接收器和 CAN2 的四台 GM6020（反馈 ID `0x205` 至 `0x208`，命令 ID `0x1FE`）。不需要云台板、3508 或裁判系统。当前电机已拆下空载，结果只能判断电控链路和电机本体；舵轮机构的间隙或共振需复装后验证。

## 编译配置

配置位于 `application/chassis_6020_bench_config.h`：

| 项 | 值 | 作用 |
| --- | --- | --- |
| `CHASSIS_6020_BENCH_TEST` | `1` | 使用台架路径；设为 `0` 编译普通底盘固件 |
| `CHASSIS_6020_BENCH_MODE` | `1` 或 `2` | `1` 为短脉冲，`2` 为闭环扫角 |
| `CHASSIS_6020_BENCH_PULSE_CURRENT` | `300` | 短脉冲四路电流命令 |
| `CHASSIS_6020_BENCH_PULSE_MS` | `150` | 短脉冲持续时间 |
| `CHASSIS_6020_BENCH_CURRENT_LIMIT` | `1500` | 扫角电流命令限幅 |
| `CHASSIS_6020_BENCH_SWEEP_RAD_PER_SEC` | `0.50f` | 摇杆满幅时目标角速度 |

在底盘根目录执行 `./AI_Workspace/tools/build.ps1 -Board chassis`。本目录的构建日志可核对编译模式和结果。修改模式后必须重新编译、由操作者烧录相应固件；不要以旧固件的运行现象判断新模式。完成调查后将 `CHASSIS_6020_BENCH_TEST` 设回 `0` 并重编普通固件。

两种台架固件分别保存于 `AI_Workspace/artifacts/6020-bench/6020-pulse.hex` 和 `6020-sweep.hex`（同目录也有 AXF）。这些是本地忽略目录中的构建产物；重新改动源码后，应重新编译并替换对应产物。当前源码配置为模式 2，Keil 默认输出也是扫角固件。

## 操作顺序

1. 上电前保证电机固定、可自由转动，两个遥控拨杆至少一个不在上档。上电后通过调试器确认 `motor_chas[4..7].ecd` 随手转变化，并检查 `can_6020_last_feedback_ms[0..3]` 持续更新。
2. **先用模式 1。** 摇杆通道 `ch[0]` 回中，再把两个拨杆都拨到上档。四台电机各收到 `+300`、持续 `150 ms`，随后自动给零电流；必须先退出双上档才能再次启用。检查 `can_6020_tx_diag` 和四台反馈电流、编码器变化。
3. 确认命令链路后，用模式 2 固件重复上一步的启用动作。四台电机分别以启用瞬间的编码器角度为起点；缓推 `ch[0]` 扫角，回中保持。当前速度上限约 `0.5 rad/s`，完整扫一圈需约 `13 s`。离开双上档立即清 PID 并发零电流。
4. 出现颤动时先退出双上档，再暂停调试器。`chassis_6020_bench_trace` 会冻结最后约 `1.28 s` 的采样：`sample` 中有四路原始编码器、目标弧度、转速、角度环输出、命令电流、反馈电流、遥控状态、反馈年龄和 CAN 错误。`samples_written` 小于 128 时看 `sample[0..samples_written-1]`；满 128 后从 `next_index` 开始循环读取。

## 诊断判读

- `last_disarm_reason`：`1` 拨杆退出、`2` DBUS 非法或超时、`3` 任一 6020 反馈超时、`4` 上次 CAN 加入发送队列失败、`5` 短脉冲结束。`state`：`0` 零电流、`1` 短脉冲、`2` 闭环扫角。
- `can_6020_tx_diag.last_status == 0` 仅表示 HAL 接受了帧进入发送队列，**不证明电机收到帧**。若 `failure_count` 增长或 `last_error` 非零，先查 CAN2 发送链路；若目标和命令电流变化而编码器与反馈电流不动，再查电机 ID、CAN 接线与电机供电。
- 若仅在固定原始编码器区间抖动，比较该处的目标、编码器、转速和命令电流是否交替跳变。先保留原 PID 值复测，再一次只改一个参数作对照，勿同时改增益和控制周期。
- 台架代码每次循环只向 CAN2 发送 `0x1FE`；不向未接 3508 的 CAN1 发送底盘电机命令。正常固件路径由编译开关恢复。

**安全边界：** 短脉冲和闭环扫角均需 DBUS 与四路反馈持续更新。失去任一条件会尝试发送零电流；若 CAN 物理链路也失效，软件无法保证零电流命令送达，应使用外部断电手段停止电机。烧录与实体测试由操作者执行。
